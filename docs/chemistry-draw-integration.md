# Chemistry-Draw integration report — DECIMER ONNX models

> **Scope:** product-facing integration brief for `chemistry-draw`. This is **not** the official benchmark report (`docs/benchmark-report.md`, neutral and auto-generated by `dtx report`) and it introduces **no new measurements**: every figure is cited from the official report or from `docs/experiments/` (Imago, preprocessing, confidence gate). Experiment results are excluded from the official report by design; here they are legitimate product evidence and are labeled as such.

---

## 1. Why integrate these models (motivation)

### 1.1 The embeddable alternative is ~59 pp worse (Imago baseline)

Imago OCR (EPAM) is the classic **embeddable, non-ML** OCSR tool — the traditional choice for shipping structure recognition inside an application. Measured on the **same frozen printed `eval-1000`** (seed `20260308`, primary metric = RDKit canonical SMILES), same protocol as our dossier ([experiment doc](experiments/imago-printed-baseline.md)):

| System | RDKit canonical (primary) | ≥70% floor | Exact string |
|---|---:|:---:|---:|
| DECIMER printed **TF baseline** | **627/884 = 0.7093** | ✅ | 12/1000 |
| DECIMER printed **FP32 ONNX (selected)** | **614/872 = 0.7041** | ✅ | 12/1000 |
| Imago 2.0.0rc1 (external, rule-based) | 69/582 = **0.1186** | ❌ | 50/1000 |

**Paired evidence (same 1000 IDs):** TF correct only **575**, Imago only **17**, both 52, neither 356 → **≈ +59.1 pp** in favor of DECIMER. Imago also produced 392/1000 incomplete outputs and 39 crashes/timeouts (resilient runner).

**Argument for integration:** on this frozen printed benchmark, embedding the DECIMER ONNX model instead of the classic rule-based tool is worth **~59 pp of primary-metric accuracy** — a paired, conclusive gap on the same images. (Caveat: applies to this frozen printed eval; Imago performance varies by image type, and its native instability in this environment is itself a product consideration.)

### 1.2 The selected models clear the acceptance floor in-domain

| Component | Selected variant | Primary metric (frozen eval) | Evidence |
|---|---|---|---|
| `ocsr-printed` | **FP32** | **0.7041** canonical (614/872, n=1000) ✅≥70% | [Official report section 5](benchmark-report.md) |
| `ocsr-handdrawn` | **FP32** | **0.7300** canonical (711/974, n=1000) ✅≥70% | Official report |
| `image-classifier` | **E4 FP16** | **0.7679** binary acc (n=754, non-reaction) ✅≥70%, TF parity 0.998 | Official report |

No tested compressed OCSR variant (E1/E3/enc-dec mixes) held the floor robustly, so **FP32 is the shipped accuracy choice** (see section 6 caveats on size/latency).

**Domain note (do not over-promise):** neither OCSR model dominates both domains — hand-drawn-on-printed scores 0.694 vs printed in-domain 0.704, and printed drops to 0.677 on hand-drawn pilot. Specialization is **non-exclusive, not superior**; a single-vs-dual-model routing choice is a product decision (section 6).

### 1.3 The confidence gate is measured, free product value

From the [confidence-gate experiment](experiments/confidence-rejection-gate.md) (experiment-only, eval-1000):

- OCSR gates are strong: **AUC 0.938 (printed) / 0.857 (hand-drawn)**. Rejecting the least-confident **15%** lifts production accuracy **0.614 → 0.7165** (printed) and **0.711 → 0.7965** (hand-drawn); the rejected set is 3.3% / 22.7% accurate — real signal, not an artifact.
- **Free:** confidence is computed during greedy decoding anyway; no model change, no extra inference cost.
- **Classifier gate rejected:** AUC 0.603; its dominant error (`several_molecules` → no-structure, 146/174 FN) is systematically confident. The classifier runs **without** a gate — do not retry gating without fixing the multi-molecule data gap.

### 1.4 What is explicitly *not* claimed

- The colored-background stress set (0.18–0.26) is **official but floor-exempt** (`floor_applies=false`): it measures robustness, not acceptance, and it confounds **color + quality + style** (color-only experiment pending).
- Experiment numbers (Imago, preprocessing, confidence gate) live in `docs/experiments/` and are **not** part of the official report.

## 2. Preprocessing: what to ship (experiment evidence)

> Source: the [preprocessing experiment](experiments/preprocessing-strategies.md) (experiment-only; screening on pilot n=300, confirmations on eval-1000; **no variant met the ≥3 pp promotion threshold** on either OCSR domain).

### Verdict: ship the current runtime pipeline unchanged (`runtime_default`) for all three models

| Model | Variant tested | Most relevant result | Decision |
|---|---|---|---|
| `ocsr-printed` FP32 | `decimer_tf_ref` (DECIMER TF gaussian+antialias resize) | eval-1000: comparable **+0.51 pp** (0.7041→0.7093), production **+1.3 pp** (0.614→0.627) — driven by fewer incompletes (23 vs 31), McNemar p=0.023 (small, not significant under correction) | **Keep PIL LANCZOS** — the TF advantage is *completeness, not recognition*; adopting it adds a TF dependency for ~1 pp. If printed completeness matters, a cheaper lever is a **retry/fallback on incomplete outputs**. |
| `ocsr-printed` FP32 | `sharpen_unsharp` | +0.76 pp pilot (SE ≈ 2.7 pp) | below promotion threshold → **no** |
| `ocsr-printed` FP32 | `no_border_crop` | **−2.42 pp and ~2.1× slower** | **keep border cropping** |
| `ocsr-printed` FP32 | `autocontrast` | −0.27 pp pilot | no |
| `ocsr-handdrawn` FP32 | `decimer_tf_ref` | −0.31 pp eval (p=0.86) — no gap (opposite of printed pilot) | keep default |
| `ocsr-handdrawn` FP32 | `no_border_crop` | **+1.09 pp** — *opposite sign* to printed (−2.42) | domain-specific, **no transfer** → keep default |
| `ocsr-handdrawn` FP32 | `sharpen_unsharp` | **−2.16 pp** — opposite sign to printed (+0.76) | no |
| `ocsr-handdrawn` FP32 | `no_binarize` | −1.61 pp | **keep the B&W/binarize step** |
| `image-classifier` E4 FP16 | `higher_contrast` | +2.26 pp overall (0.7679→0.7905) — **but the gain comes entirely from `several_molecules`** (+6.8 pp there); the product slice `one_molecule` is flat (0.8848→0.8807, −0.4 pp) | **not promoted** — no benefit where chemistry-draw needs it |
| `image-classifier` E4 FP16 | `sharpen` +1.46 pp / `autocontrast` +1.19 pp | small, unvalidated on real inputs | no |

### Hard rules (measured on all three models)

- **NEVER auto-invert.** Harmful everywhere it was measured: hand-drawn OCSR **0/289 canonical** (validity collapses to 0.653, 34.7% incomplete), classifier **−14.85 pp**. Product rule: *never invert scans/photos, regardless of background.*
- **Never histogram-equalize** (classifier −14.19 pp).
- **No sharpening/autocontrast in the default path** — winners **flip by domain** (printed vs hand-drawn), so there is no assumed transfer; validate any future change per model on eval before shipping.
- **Keep the binarization/contrast-boost step** (removing it costs −1.61 pp on hand-drawn).

### What the pipeline does today (validated as-is — no change required)

- **OCSR:** transparent→white, contrast stretch, B&W (contrast 1.8), empty-border crop, central square, brightness ×1.6, **PIL LANCZOS resize to 512×512**, ImageNet mean/std normalization.
- **Classifier:** RGBA→white background, grayscale→RGB, aspect-preserving resize + white pad to 224×224.
- **Model choice by input type** (DECIMER's `hand_drawn` flag equivalent) is the primary "preprocessing strategy" — consistent with our non-exclusive specialization finding (section 1.2): match the checkpoint to the image style rather than filtering the pixels.
- The DECIMER API exposes **no tunable preprocessing knobs** (fixed pipeline, no TTA/denoise options); confidence is only for gating, never for changing the prediction.

## 3. Behavior contract: what the app does per image type

| When it arrives… | What the model does | What your app should do |
|---|---|---|
| **Normal image** (black & white, one molecule) | Correct **~70–73%** (printed 0.7041 / hand-drawn 0.7300 canonical, frozen eval) | **Return the SMILES.** Done. (Confidence ≥ threshold → high certainty of being in that 70–73% band.) |
| **Dubious image** (blurry, cropped) | **Low confidence** — the errors concentrate at the bottom of the confidence ranking (rejected-set accuracy 3.3% printed / 22.7% hand-drawn at 15% rejection) | **"I couldn't read it confidently; try a sharper image."** The confidence gate already tells you which image is dubious — you don't need a new detector for this case. |
| **Rare-type image** (colored, photo, hand-drawn style fed to the printed model) | **Fails a lot: 0.18–0.26** canonical on the stress set (printed 0.1806 / hand-drawn 0.2558, section 5.C of the official report) — and even what the gate *retains* there is only **~30% correct** (26/86 printed, 43/137 hand-drawn) | **"This type of image isn't well supported yet."** Not *"try again"* — it's *"not for this"*. Pair the gate with an explicit image-type/OOD check: on stress images the gate rejects 57%/31.5%, but ~70% of what it keeps is still wrong, so confidence alone is **not sufficient** here. |

Reading the rows: row 1 is the product; row 2 is the **confidence gate doing its job** (convert "sometimes wrong" into "sometimes I don't know"); row 3 is an **honest capability boundary** — the message must differ from row 2, because retrying the same image type will not help.

## 4. v1 routing (reference implementation sketch)

**Important: the classifier is BINARY (0/1).** It outputs a single logit → sigmoid → `structure` / `no-structure` (`src/toolchain/benchmark_run.py`, threshold `0.000089`). The four benchmark categories (`one_molecule` / `several_molecules` / `other` / `reactions`) are **dataset labels used to evaluate the binary output per slice** — the model cannot distinguish them. Any routing beyond binary needs a separate signal (see below).

```
image → classifier E4 FP16 — BINARY: structure(1) / no-structure(0)
        (NO confidence gate on it — rejected, AUC 0.603)
  │
  ├── "no-structure" (0) → "no structure detected"
  │     reliable when the image truly has none (0.9962 on `other`),
  │     BUT ~58% of multi-molecule images also land here (146/250
  │     `several_molecules` predicted no-structure) → user is wrongly
  │     told "no structure" for an image that HAS structures
  │
  └── "structure" (1) → OCSR (selected ckpt) + confidence gate
        ├── conf ≥ threshold → return SMILES          (row 1: single-molecule images)
        └── conf < threshold → "couldn't read confidently; try a sharper image"  (row 2)

NOT derivable from this binary classifier (needs a separate signal — data/model gap):
  • several_molecules → "crop to one" prompt: candidates are (a) post-hoc check of the
    OCSR output for '.' fragment separators, (b) a region/multiclass detector.
    Unmeasured today; the classifier alone cannot route here.
  • reactions → "not supported yet": the model also emits binary on reactions
    (174 structure / 72 no-structure of 246) but there is no correct binary label —
    excluded from the metric as ambiguous. Reaction detection is unmeasured.
```

Classifier per-category numbers are **binary-accuracy slices by true label** (eval-1000): `one_molecule` 0.8848, `other` 0.9962, `several_molecules` 0.4160 (dominant failure: 146/174 FN are `several_molecules` → no-structure, systematically confident — hence no gate on the classifier); `reactions` excluded from binary.

**Rare-type handling (row 3)** sits beside this tree: an image-type/OOD signal (or a sustained high rejection rate) routes to the *"not well supported"* message instead of the retry message.

## 6. Caveats and pending decisions before shipping

1. **Confidence thresholds are in-domain.** 0.928 (printed) / 0.901 (hand-drawn) were calibrated on frozen `eval-1000`. Re-calibrate on real chemistry-draw inputs before shipping; do not hardcode. On the stress set the same thresholds reject 57.0% / 31.5% (vs ~15% in-domain) — the shift is detectable, but the operating point moves.
2. **Operating point is a product decision** (85% vs 80% vs 70% coverage — trade-off table in the confidence-gate experiment), not a benchmark result.
3. **Rejection needs a UX path** ("reject and guide", with actionable copy) — see the experiment doc for wording and rationale.
4. **Size/latency:** FP32 OCSR artifacts are **301.2 MB** (enc+dec) with p50 ~1.1–2.3 s on CPU — acceptable for desktop, a decision for mobile/edge (no compressed variant held the ≥70% floor, so compression currently costs acceptance).
5. **Model routing:** single vs dual OCSR model (printed-only vs handdrawn-only vs classifier-routed) is still open; neither model is uniformly better across domains.
6. **Stress/rare-type detection:** the confidence gate is necessary but not sufficient for row 3; an explicit image-type/OOD check is recommended. The color-only controlled experiment is pending (stress set confounds color + quality + style).
7. **Preprocessing:** the default pipeline is validated **on the frozen sets only** (section 2) — re-validate on real chemistry-draw inputs before changing anything; the one invariant measured across all three models is **never auto-invert**.
